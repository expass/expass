---
title: "🌍 Community & research"
---

Support ExPass by sharing where you use it, contributing measurements, or
publishing research. These contributions help explain how the library behaves in
real applications and guide future improvements.

## 🚀 Share your website or application

If your project uses ExPass, we'd like to hear about it. You can acknowledge ExPass
on your website, in your application's credits, or in your repository's README.
For example:

> Password encoding powered by [ExPass](https://github.com/expass/expass).

[Open an issue](https://github.com/expass/expass/issues/new) to share your project,
or propose a documentation addition through a pull request. Include:

- Your project's name and public URL.
- A short description of what it does and how it uses ExPass.
- Any integration experience or feedback you would like to share.

Mentioning ExPass is optional; you can contribute feedback without publicly naming
your application.

## 📊 Contribute benchmarks

Share a reproducible benchmark through an issue or pull request, with the script
or repository needed to run it. Include:

- ExPass and Node.js versions, operating system, and CPU and memory details.
- Encoding and verification options, including work factors and output lengths.
- Concurrency, sample count, warm-up procedure, and measurement method.
- Results with units: latency, throughput, and memory use where measured.

For comparisons with other libraries, include their versions and full parameters,
explain why you chose those settings, and use the same hardware and workload.
Numeric cost values across different algorithms are not directly equivalent.
Distinguish measurements from estimates and explain the limits of your results.

## 🔬 Share papers and technical analysis

We welcome papers, independent reviews, technical articles, and experiments about
ExPass or its design. Share a public link through an issue, together with:

- A short summary of the question investigated and the findings.
- The library version or commit studied.
- The assumptions, methods, and limitations of the analysis.
- Supporting code, data, or reproduction instructions when available.

Findings that identify weaknesses or suggest improvements are valuable too. If the
work suggests a code or documentation change, link the corresponding issue or
pull request so the discussion remains connected to the evidence.

## 📣 Help others discover ExPass

Tutorials, integration examples, talks, and translations can help new users get
started. Link to the documentation and identify the version used in your examples
so readers can reproduce them.

You can also support development through [code contributions](./code-contribution.md)
or a [donation](./donate.md).
